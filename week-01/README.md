### **root vs. IAM vs. Shared Responsibility Model**

*Describing what root vs. IAM vs. Shared Responsibility Model means*

The best way to think about the root is as the owner. It has full control over the AWS account and functions, including the billing, security, etc. There is only one root and it is detrimental if compromised, so the best practice is to create IAM accounts to carry the daily tasks. Speaking of IAM user, we can think of it as a manager, which is given access to the AWS account to carry out everyday work. The root can remove the IAM whenever it would like and since the IAM is an extension of what was created from the root (having controlled permissions to what it has access to), it is considered to be more safer since it is quite trackable, controllable, and has the ability to recover things more easily if compromised. The AWS Shared Responsibility Model is the concept there is a shared responsibility between customers and the AWS environment/platform to keep the AWS information secured and safe. For one, it is AWS responsibility to handle security of the cloud while the customer handle the security in the cloud by, for example, setting up security groups to control inbound and outbound traffic for their cloud resources.
